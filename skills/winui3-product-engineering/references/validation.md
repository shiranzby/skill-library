# Windows 实际验收矩阵

不要把 XAML 可解析、源码检查或截图当作完整成功。每个结论写目标构建、Windows 版本、DPI、输入方式和证据。

## 静态与构建

- 确认 `Microsoft.WindowsAppSDK`、Windows SDK、TargetFramework、打包方式和平台（x64/x86/ARM64）。
- `dotnet build`、XAML 编译、警告为零（若环境缺 SDK，报告缺失，不声称通过）。
- 解析 XAML/XML，检查引用的控件命名空间和资源；对仿 Fluent Rust 项目检查 Rust 编译与资源加载，而不是套用 WinUI 构建结论。
- 记录当前 WinUI Gallery 参考 commit 和 MIT 许可证，不将远程源码视作当前项目运行证据。

## 真实交互

| 场景 | 通过条件 |
| --- | --- |
| 打开/收起设置 | 设置窗口唯一；托盘/快捷入口复用同一窗口；隐藏不退出进程，配置仍可恢复 |
| Toggle/Radio/NumberBox/TimePicker | 鼠标真实点击和键盘操作均改变状态；非法输入保留原稿或报错；自动保存成功/失败可见 |
| 取消/失败 | 取消零写；失败不丢输入；重试使用同一草稿；迟到异步结果不能覆盖新选择 |
| 标题栏 | 系统按钮、拖动、缩放、右键菜单、Esc/Alt+F4 与高对比度均成立；自定义标题栏交互区不吞点击 |
| 单实例/托盘 | 第二次启动不创建第二套状态；第一实例获得焦点并处理唤起；退出清理托盘、热键和硬件状态 |
| 热键 | 捕获期间原热键不执行动作；冲突恢复旧热键；ESC 取消；长按不会重复；键盘布局按真实 VK 验证 |

## 键盘、UIA 和视觉

- Tab 顺序完整；RadioButtons 用箭头导航；按钮 Enter/Space；文本框有可见焦点；检查 Narrator/Accessibility Insights 的可访问名称和状态。
- 100%、125%、150%、175%、200% DPI 运行并截图；验证文字、卡片、标题栏、命中区没有重叠或裁切。有效像素与物理像素分开记录。
- 窗口宽度至少覆盖小于 640、641–1007、1008 以上的有效宽度；检查窄窗滚动、单列重排、标题和错误文本；不要用截图比例替代 computed/client geometry。
- 浅色、深色、高对比度、文本缩放和减少动画设置分别检查；颜色不能是唯一状态线索。
- 桌面系统工具验证托盘、系统 caption buttons、鼠标拖动和快捷键；平板验证 40/44 epx 触区、触控滚动、横竖屏和软件键盘；窗口化验证调整大小时不出现横向溢出；可折叠设备只有在真实设备或明确仿真器上实测后才能报告通过。
- 同一功能至少走鼠标、触控（若适用）、键盘和 UIA 四条路径；hover、鼠标坐标或截图不能代替触控和键盘证据。

## 系统边界

- WMI、DDC/CI、HDR、远程桌面、显示器拓扑变化、权限不足和异常退出单独测试；没有硬件或权限时验证降级提示与恢复文件，不假报成功。
- 采集状态：是否创建了全屏遮罩、是否排除屏幕捕获、光标和亮度是否恢复、DWM/Explorer 重启后托盘是否重建。
- 后台测试不抢用户前台窗口，不结束非自有进程；硬件调光测试应记录原始亮度并在 finally 恢复。
