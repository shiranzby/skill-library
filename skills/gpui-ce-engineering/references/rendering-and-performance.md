# 渲染、缓存与实测

GPU 渲染适合复杂合成、自定义绘制和高交互密度；总成本仍包含字体发现、shape/layout、entity树、CPU帧数据、glyph atlas、纹理、GPU表面和驱动。无需变化的视图使用事件驱动失效，不建立常驻60/120FPS循环。

- 大集合虚拟化只创建可见范围及合理预取；列表项身份按业务 ID 固定，不能只按当前索引。
- 纹理/字形 atlas 限额需计入色彩字形和高DPI峰值；窗口/主题/字体版本改变时正确失效。
- 弱引用和订阅所有者明确，窗口关闭后任务、observer和GPU资源可释放；单纯 `Arc` 数量少不证明占用低。
- 把矩阵区分为空窗口、真实页面、大列表、编辑器、多窗口，记录CPU与GPU私有/共享内存、帧耗时、输入延迟和冷启动。
- 固定同场景/字体/DPI/构建模式比较；不要把upstream benchmark或另一台机器的数值当作本项目结果，也不凭框架名宣称更省内存。

改变窗口、渲染或输入架构前，先做一条可交付的真实页面验证，覆盖中文IME、Tab/快捷键、保存失败、关闭/隐藏/唤起、最大化/还原、多显示器DPI和图形设备变化。支持平板时增加触控滚动与软键盘；平台缺失单独报告。
