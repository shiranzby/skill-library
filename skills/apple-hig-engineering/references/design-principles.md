# 核心设计原则

本页是对 Apple HIG [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)、[Foundations](https://developer.apple.com/design/human-interface-guidelines/foundations)、[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback)、[Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy) 和 [Writing](https://developer.apple.com/design/human-interface-guidelines/writing) 的原创工作摘要。它们是取舍工具，不是必须全部同时满足的视觉模板。

## 用八个问题做取舍

| HIG 方向 | 实施时问什么 | 可验证信号 |
| --- | --- | --- |
| Purpose | 这个页面/动作完成哪个用户目标？ | 首屏有清楚的主要任务；无关装饰不抢焦点。 |
| Agency | 用户能否控制开始、取消、退出、重试和撤销？ | 长任务可取消；不可逆动作有清晰确认；取消不会偷偷提交。 |
| Responsibility | 数据、权限、失败和副作用是否透明？ | 请求权限前说明用途；错误给修复路径；保留失败输入和恢复入口。 |
| Familiarity | 是否使用目标平台已有的控件、手势、菜单和术语？ | 键盘、指针、触摸、VoiceOver/辅助功能路径与平台预期一致。 |
| Flexibility | 同一目标是否有适合不同能力和输入方式的路径？ | 动作有按钮/菜单/快捷键等替代；窗口变窄或字体放大仍可完成任务。 |
| Simplicity | 是否只显示当前决策需要的信息？ | 选项按任务分组；默认值可用；设置项和层级保持克制。 |
| Craft | 细节在真实内容、语言、动态字体和状态下是否成立？ | 长文本、空态、错误态、深浅色、对比度和缩放经过检查。 |
| Delight | 反馈是否让人感到有响应且不打断？ | 动效有因果且可停止；重要反馈不只靠颜色、声音或动画。 |

## 信息层级和视觉

- 先用布局、字重、间距和对齐建立层级，再考虑颜色、材质和动效。Apple 的系统颜色是语义 API，不要把某个截图中的 RGB 值当成固定规范。
- 内容优先。媒体上方的徽标或倒计时应小而克制；全屏、沉浸和 Always On 场景要避免遮挡关键内容、造成灼屏或让用户失去环境感知。
- 深色外观使用语义色和 base/elevated 层级，不要简单反色。视觉意义不能只由颜色传递，需配合文字、图标、形状或状态说明。
- 动效表达状态因果、方向和完成度；它应短、可中断，并尊重减少动态效果设置。加载动画不能代替真实状态机。
- 系统字体、系统文字样式和 SF Symbols 能随平台与可访问设置适配；自定义字体或图标需要重新验证字重、回退字体、基线和本地化长度。

## 状态、反馈和恢复

用显式状态建模，而不是用一个布尔值掩盖过程：`idle → loading → ready/empty → failed → retrying`。每个状态至少回答“发生了什么、还能做什么、数据是否已保存”。

- 附近且不重要的反馈用就地状态、轻量提示或非阻塞进度；只有重要、可操作、意外或不可逆的数据损失才打断。
- 进度已知时显示确定进度；未知时不要伪造百分比。长任务支持取消；取消后释放资源并保持一致的界面状态。
- 非模态 popover/sheet 因外部点击关闭时保存已输入内容；只在明确点击 Cancel 时丢弃。一次只打开一个层级，避免层层覆盖。
- 破坏性动作提供清晰的后果和可恢复路径。能撤销就优先 Undo；不能撤销时应在动作前说明范围，不把确认弹窗用于每个普通操作。
- 错误消息靠近问题，避免责怪用户，描述下一步。空态是临时状态，应给出可执行的下一步，不要在空态放会消失的关键说明。

## 权限、隐私和生成内容

- 只在功能确实需要时请求最少权限，最好在用户进入相关任务后请求；用途说明用短句、主动语态和真实数据流描述。
- 自定义“预授权”界面只能清楚地把用户带到系统弹窗，不能仿造系统界面、用诱因操纵选择或提供会绕开选择的额外按钮。
- 能在设备上处理就避免不必要的上传；敏感信息在锁屏、Live Activity、widget 和截图中脱敏。删除、同步冲突和离线行为要有明确语义。
- 生成式/机器学习结果应标示生成性质、能力边界和不确定性；提供非 AI 回退、可修正且持久地应用修正，不在未经校准时显示虚假置信度或臆测情绪。

## 文案和本地化

- 先建立产品词汇表和 voice，再按上下文调整 tone。句子简短、主动、可翻译，避免行话、性别化和不必要的“我/你的”。
- 按钮和链接优先使用描述动作的动词；设置标签描述开启后会发生什么。多步骤流程统一使用 `Get Started`/`Continue`/`Next`/`Done` 一类的过渡词。
- 输入框有可见标签和格式提示；错误说明正确格式或修复方式，而不是只写 `Invalid`。空屏和无结果页面给出明确下一步。
- 按目标设备使用 tap/click 等准确动词；测试不同语言、日期/数字格式、长文本、从右到左布局和系统字体回退。
