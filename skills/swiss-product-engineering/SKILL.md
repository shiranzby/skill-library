# 有秩序的产品工程

目标：**高信息密度 × 低视觉噪音 × 完整交互闭环 × 可验证交付**。极简是隐藏网格带来的秩序，不是删边框、大留白或缩小控件。

## 使用边界与按需阅读

- 先读当前项目入口、设计合同与最新交付；区分当前事实、长期要求、历史证据。用户本次要求优先，不覆盖已有品牌与平台约束。
- 本 Skill 提供跨产品默认，不照搬工作台栏目、业务对象、账号、本机路径或版本编号；沿用项目技术栈，不强加 Electron、数据库、部署或重构。
- 页面、布局、控件、主题、动效任务：完整阅读 [组件与布局](references/components-and-layout.md)。
- 状态、接口、持久化、外部集成、测试、发布任务：完整阅读 [工程与交付](references/engineering-and-delivery.md)。全栈功能读取两份；纯文案修改不加载无关参考。
- 将本 Skill 带到新仓库或新产品：先阅读 [跨项目适配](references/project-adaptation.md)，再把项目自己的入口、约束、数据和发布边界补到任务上下文。
- 分析请求只分析；实现请求才改代码。新外部写操作、账号操作与生产更新不因调用本 Skill 自动获准。

## 设计宪章

| 概念 | 决策规则 |
| --- | --- |
| Swiss 约 70% | 主辅比例、共同边缘、文字基线、列轨道、稳定间距；用结构建立层级 |
| Apple 约 30% | 清晰语义、即时反馈、键盘可达、可逆操作、焦点恢复、短而可打断的动效 |
| 内容先于容器 | 先确定主动作、正文和上下文，再决定分栏；不把所有功能包成等权卡片 |
| 密度不等于拥挤 | 去重事实、合并重叠工作面、共用工具带；不缩正文或触区，不用假数据填空 |
| 中性视觉 | 默认黑白灰；夜间中性灰黑；颜色只表达状态、选择或明确品牌语义 |
| 克制装饰 | 无默认粉紫蓝配色、绿底、渐变、辉光、漂浮背景、多层玻璃或圆角卡墙 |
| 动作可读 | 高频动作直达，低频按需；每工作面至多一个 Filled 主行动，不堆装饰箭头和英文眉题 |
| 语义保真 | 链接能打开，标签有独立身份，四象限真二维，日历保持可读，不以隐藏主要内容伪造密度 |

## 视图模式不是换皮

当一个工作面同时提供多种阅读方式时，**设计风、数据风、卡片风是三种任务模式，不是同一页面换颜色或阴影**：

- **设计风**：系统结论 → 待处理事项 → 对象摘要 → 最近变化 → 下一步；控制首屏焦点和叙事顺序，减少扫描噪音。
- **数据风**：范围／筛选 → 汇总指标 → 行级对象 → 异常和趋势；表格优先，列轨道稳定，适合排序、比较和批量操作。
- **卡片风**：一个对象一张紧凑卡；保留状态、关键数值和主动作，适合快速浏览与中等数量对象。数量增大时自动转为分组列表或表格。

三种模式必须共享同一对象 ID、状态、筛选范围和写入命令；切换只改变呈现，不复制数据、不丢选择、不伪造统计。每个页面可以声明自己的可用模式，设置页可以逐页保存偏好；不能只改标题、阴影、背景或“设计／数据”字样来冒充差异。

窄屏下（通常 ≤639px）三段式模式控件收敛为一个显示当前模式的循环按钮（点击切换到下一模式），为搜索和页面动作让出空间；不得造成顶栏横向溢出、搜索框不可用或触控命中重叠。宽屏保留分段控件。模式控件的实际 DOM、计算宽度、可达性和切换结果必须有回归断言。

长域名、Zone、密钥名称、URL 等唯一身份在有空间时完整展示；允许自然换行和断词，不用省略号隐藏可区分信息。只有摘要且存在明确的全文入口时才可截断。并排卡片只在职责相同且需要形成比较时统一高度，不用巨大最小高度填空白。

抽屉／详情面板打开时压缩正文并从对应边缘滑入，关闭时反向收回；动效约 180–280ms、可中断，支持 Esc、关闭后归焦。展开前先确定最小正文宽度和卡片最小可读宽度：空间足够时保持原有卡片列数，只压缩列间空隙和卡片宽度；空间不足时允许减列、改用分组列表或受控局部滚动，但不能把内容压到不可读。过渡期间不得出现横向滚动条闪烁或内容裁切；展开／收起前后需验证 `scrollWidth ≤ clientWidth`（或明确的局部滚动责任）、焦点归属、`aria-expanded` 与 `aria-controls`。整行可打开详情时，内部按钮必须阻止冒泡并执行自己的命令；不要把不可点击的文字伪装成按钮，也不要使用无语义的装饰箭头。

## 推进方式

1. **定义一个真实场景**：使用者／入口／对象／主动作／成功结果／失败恢复。列清本次范围与不做事项；信息充分直接执行，不重复问卷。
2. **拆职责而非拆卡片**：页面、模块、状态所有者、共享数据、操作入口；功能重叠优先共享对象与视图，不复制数据。
3. **研究关键模块**：新建或重做重要模块时，定向检查成熟产品或开源组件的当前截图、交互、代码与 License；优先现有依赖，按成本选少量候选，不为每个小控件重新搜索。记录来源版本／借用点／适配边界。
4. **先稿后融合**：较大 UI 改造先给关键模块稿，校正网格与真实内容预算，再整合整页。OpenDesign MCP 如可用用于出稿和比较；不可用如实说明，不阻塞修复，不声称未执行的参考或复用。
5. **完成纵向闭环**：UI 操作 → 领域命令 → 存储或服务 → 状态反馈 → 切换／重启恢复。原 ID、原文、草稿、自定义顺序与数据归属不变；Mock 必须标明。
6. **先定向，再阶段回归**：先复现真实问题和反例，再作最小有效修复；结构确需重构可扩大改动，但逐项对应需求，禁止无目标微调或顺手清理。
7. **当前产物验收**：构建、真实交互、几何、当前截图目视分别成立；相关模块通过后检查整页共同网格与跨页一致性。用户复现或视觉拒绝出现时重开，不以测试数量辩解。

## 实施底线

- **前端**：视图、交互状态、领域状态分离；失败保稿、取消不误写、切换保位置；状态与可访问语义同步。
- **后端／IPC**：边界校验、稳定身份、明确错误、原子提交、可恢复迁移；外部依赖隔离，不把服务失败包装为成功空集。
- **资源**：异步有界、迟到保护、取消可收束；后台服务按需启动，不为一个小功能常驻多套浏览器或无界重试。
- **数据**：用户原件不作测试夹具；账号副本仍连接真人远端，不能当沙箱。同步失败保留可用缓存，不共用活跃可写 Profile。
- **状态语义**：当用户可采取的动作不同，权限不足、未启用、无数据、上游未返回、超时／离线、部分成功和读取失败应分开呈现；加载、确认空集和过期缓存也要有可辨识状态。显示缓存时标注来源与更新时间，不能把缓存值冒充当前值；错误详情按权限最小化，不能为解释状态泄漏敏感上游内容。
- **日用不受扰**：测试独立数据／端口／进程；后台验证不抢前台键鼠、窗口或焦点，不停止用户进程，不热改日用产物。

## 交付表达

简短列出：**实际变化｜验证证据与目标版本｜未完成／限制｜运行入口与回退**。把本轮确认的稳定决策写入项目已有规范或经验文件；更新当前入口，不追加互相矛盾的“最新”结论，不擅自修改其它项目或全局记忆。

真实前端演示必须来自仓库当前前端构建（可注入静态适配器和合成数据），不能另造一份看起来相似的 HTML。演示明确“不连接 API／数据库／Cookie／Token”；生产构建、Pages 演示和本地候选分别验收，不能用演示通过替代生产发布成功。

生产发布要记录代码提交、构建结果、部署工具／工作流、外部版本或 URL、健康检查和资源指纹。凭据只从本机登录态、环境变量或托管 Secret 读取，不写入仓库、日志、截图或文档；缺少凭据时报告阻塞，不猜测、不从业务页面反向提取部署权限。

完成判据：用户能找到入口、完成主动作、获得可信反馈、失败后继续工作。静态样式、构建绿灯、截图数量都不能替代这个结果。
