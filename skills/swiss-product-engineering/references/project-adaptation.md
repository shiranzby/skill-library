# 跨项目适配清单

本 Skill 是方法与决策基线，不是工作台模板。迁移到其它仓库时按下表筛选，避免把一个产品的栏目、颜色、账号或技术栈误当成通用需求。

## 继承与重定制

| 可直接继承 | 必须按项目重定制 |
| --- | --- |
| 隐含网格、共同锚线、主辅职责、信息密度原则 | 品牌色、字体、平台材质、圆角、动效幅度 |
| 正文可读性、触区、键盘／焦点、失败保稿 | 领域对象、页面名称、工作流、权限与角色 |
| 单一事实源、稳定 ID、保存／取消／恢复语义 | 数据库／文件格式、IPC／API、部署与观测方式 |
| 定向反例 → 阶段回归 → 当前截图目视 | 日用／测试目录、账号来源、候选版本与回退策略 |
| 错误分类、缓存保留、迟到响应保护 | 第三方服务、解析器、浏览器容器与扩展兼容范围 |

## 迁移顺序

1. **识别项目边界**：记录仓库根、启动入口、持续文档、运行环境、默认数据位置和当前未提交修改；不覆盖脏工作树。
2. **定义真实闭环**：挑一个高频纵向场景，写出对象、主动作、成功、取消、失败保稿、重启恢复；先验证能用，再扩展页面数量。
3. **映射视觉令牌**：把本项目已有 tokens 映射为背景／表面／文字／分隔／焦点／状态语义；检查真实 computed 值和对比度，不把示例像素直接复制。
4. **映射控件矩阵**：只采用当前产品需要的组件；组件的交互状态、键盘路径、空态与错误状态必须落到真实 DOM／原生 API。
5. **建立测试分层**：先写能复现用户问题的定向测试，再接入构建、交互、持久化、几何和目视证据；外部实况与 fixture 分开记录。
6. **隔离交付**：明确日用、开发、测试、候选的代码／数据／Profile／端口；后台验证不得抢焦点或改动日用实例。只把当前候选与一个回滚候选作为常用入口。

## 适配后的停止检查

- 页面主动作是否在首屏、可发现且只有一个视觉主焦点？
- 标题、正文、工具和操作是否共享网格与文字基线？
- 长标题、长 URL、空数据、错误、深色和窄窗口是否仍可读、可达、不溢出？
- 保存、取消、失败、重试、切换和新进程恢复是否拥有明确证据？
- 是否把某个产品的业务词、假数据、登录 Cookie、本机路径或历史测试数误写进了通用规范？

若任一项未回答，标记为未完成并保留边界；不要用“构建通过”或“截图很多”替代产品验收。
